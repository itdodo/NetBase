# NetBase 业务模块开发规范（AI 协作版）

> **文档性质**：本规范约束在 NetBase 框架上开发**业务功能**时的全部代码行为。任何 AI 会话或开发者在业务分支上新增/修改业务模块，**开工前必须先完整阅读本文档**，交付时逐条自检。
>
> 框架层（本仓库 main 分支）与业务层的边界由本文档定义；框架自身的变更见 [技术文档.md](技术文档.md) 第六节开发约定。

## 一、目录边界（最重要的规则）

**框架层与业务层物理隔离，禁止互相污染：**

| 内容 | 位置 | 说明 |
|---|---|---|
| 框架实体/服务/控制器 | `表名 sys_*`、`Service/Sys`、`Controllers/System|Monitor|Auth` | 随框架演进，业务分支只读 |
| **业务实体** | `NetBase.Model/Entities/Biz/` | 表名 `biz_*` 前缀 |
| **业务 DTO** | `NetBase.Model/Dtos/Biz/` | |
| **业务服务** | `NetBase.Service/Biz/` | 命名 `XxxService`，继承 `BaseService<T>` |
| **业务控制器** | `NetBase.Api/Controllers/Biz/` | 路由 `api/v1/biz/{module}/...` |
| **业务种子** | `NetBase.Repository/DbContexts/BizSeeder.cs`（业务分支创建） | 与框架 `DbSeeder` 分离 |
| **业务前端 API** | `web/src/api/biz/{module}.ts` | |
| **业务前端页面** | `web/src/views/biz/{module}/index.vue` | |

**禁止事项**：
- ❌ 业务代码写入任何 `Sys` 前缀目录 / `System|Monitor` 控制器目录
- ❌ 业务菜单/种子写入框架 `DbSeeder`（业务分支自建 `BizSeeder`，由 Program 调用）
- ❌ 修改框架核心机制（SqlSugarContext / 仓储 / 过滤器 / 中间件）——确需扩展时先在框架层讨论

**框架层变更**（修复 bug、增强能力）在 main 进行，定期 merge 到业务分支。

## 二、建表规范

1. 表名 `biz_{模块}_{含义}`，如 `biz_customer`、`biz_customer_contact`
2. 主键**不自增**：`Id bigint`（雪花 ID 由框架插入时自动填充）
3. 必备审计列（框架 `BaseEntity` 已含，建表 SQL 需包含）：`CreateTime/CreateBy/UpdateTime/UpdateBy/IsDeleted`
4. **数据权限列**（需要数据隔离的业务表）：`DeptId bigint not null default 0` + `OwnerUserId bigint not null default 0`
5. **每列必须写注释**（扩展属性 MS_Description）——实体注释、前端表头、接口文档全部来源于此
6. 字符串列指定长度；金额用 `decimal(p,s)`；状态类列在注释中枚举取值

```sql
CREATE TABLE biz_customer (
  Id bigint NOT NULL PRIMARY KEY,
  CustomerName nvarchar(100) NOT NULL,
  ContactPhone nvarchar(20) NULL,
  DeptId bigint NOT NULL DEFAULT 0,        -- 数据权限：所属部门
  OwnerUserId bigint NOT NULL DEFAULT 0,   -- 数据权限：归属人
  CreateTime datetime NOT NULL,
  CreateBy nvarchar(50) NULL,
  UpdateTime datetime NULL,
  UpdateBy nvarchar(50) NULL,
  IsDeleted bit NOT NULL DEFAULT 0
);
EXEC sp_addextendedproperty 'MS_Description', N'客户表', 'SCHEMA','dbo','TABLE','biz_customer';
-- 每列同理 sp_addextendedproperty
```

## 三、各层开发模板

### 3.1 实体（`Entities/Biz/`）

- 继承 `BaseEntity`（自带 Id雪花/审计/软删除）
- 需要数据权限 → 实现 `IDataScope`（`DeptId`/`OwnerUserId` 用**真实列**，禁止 IsIgnore 计算属性）
- 每属性 `[SugarColumn(ColumnDescription = "注释")]`，可空标 `IsNullable = true`
- ID 语义 long 属性加 `[JsonConverter(typeof(NetBase.Common.Json.LongToStringConverter))]`

### 3.2 DTO（`Dtos/Biz/`）

三件套：`XxxQueryDto : PageQuery`（筛选字段）/ `XxxSaveDto`（入参，DataAnnotations 验证必须齐全）/ `XxxDto`（出参）。
雪花 ID 字段同样标注 `LongToStringConverter`。禁止在 DTO 上偷懒省略验证特性——服务端校验是安全底线。

### 3.3 服务（`Service/Biz/`）

- 继承 `BaseService<T>`（自带 CRUD/分页/事务/GetRequired）
- 查询条件用 `Expressionable.AndIF` 链式（勿手写 hasCondition 样板）
- 多表操作必须 `Repository.TransactionAsync` 包裹
- 映射用 Mapster `Adapt<T>`；集合查询用 `GetListAsync/GetPageListAsync`
- 文案抛 `BusinessException(msg, ErrorCodes.XXX)`——**必须查码表赋码**（`ErrorCodes` 常量，总表见 [错误码.md](错误码.md)，码只增不改不删）；需非 400 码用 `BusinessException(msg, ApiResultCode.X, ErrorCodes.Y)`

### 3.4 控制器（`Controllers/Biz/`）

- 继承 `BaseController`；路由 `api/v1/biz/{module}/...`
- 每个端点打 `[HasPermission("biz:{module}:{action}")]`；创建类加 `[NoRepeatSubmit]`
- 操作人一律 `OperatorName`；返回统一 `Success/SuccessId`；注释必须写（进 Swagger）

### 3.5 前端

- API：`api/biz/{module}.ts`，类型与后端 DTO 对齐（雪花 ID 用 string）
- 页面：`views/biz/{module}/index.vue`，列表页用 `usePageList`；`defineOptions({ name: 'Biz{Module}View' })`（keep-alive 约定）
- 权限按钮：`v-permission="'biz:{module}:add'"`

### 3.6 菜单与权限码

- 权限码约定：`biz:{模块}:{动作}`（list/add/edit/delete/export/...）
- 菜单数据由业务分支的 `BizSeeder` 写入（框架只保证 admin 角色存在）；
  **注意**：新增权限码后，需在角色管理里给对应角色授权（含 admin——增量权限码不会自动授权，参照 `DbSeeder.EnsureCrudButtons` 模式）

## 四、AI 协作约定

1. 开发业务模块的会话，**第一步先读本规范与技术文档**
2. 交付自检清单：`dotnet build` 0 错误 → `dotnet test`（单元 31 + 集成 22）全过 → `npm run type-check` 零错误 → 关键路径 curl/浏览器实测
3. 涉及新表/新接口/新权限码，交付时同步更新技术文档变更记录
4. 不确定的设计决策（数据权限是否需要、表结构怎么定）先问用户，不要擅自拍板

## 接入审批流（业务单据通用模式）

单据需要审批（如采购申请、报销）时，审批逻辑全部由框架层 `FlowEngine` 承担，业务侧仅 4 个触点：

1. **建单据**：`biz_{模块}` 表 + 状态列（0草稿/1审批中/2已通过/3已拒绝/4已撤回，参考 `BizDocStatus`）+ 表单页（业务开发规范照旧）
2. **提交审批**：单据页"提交"按钮调业务接口，服务内一行接入引擎：
   ```csharp
   await flowEngine.SubmitAsync(new FlowSubmitRequest {
       FlowCode = "purchase_request",          // 流程编码（管理员在"流程管理"页配置）
       BusinessTable = "biz_purchase_request", // 单据表名
       BusinessId = id,                        // 单据ID
       Variables = new() { ["amount"] = doc.Amount } // 条件分支变量（如金额路由）
   });
   ```
3. **实现回调** `IFlowBusinessHandler`（一个类两个方法；**按业务表名注册**，勿按流程编码——编号自增且绑定可换）：
   ```csharp
   public class PurchaseRequestFlowHandler(IRepository<BizPurchaseRequest> repo) : IFlowBusinessHandler
   {
       public string BusinessTable => "biz_purchase_request";
       public Task<string> GetSummaryAsync(long id) => ...;   // 待办标题
       public Task OnFinishedAsync(long id, FlowInstanceStatus s) => ...; // 终态回写单据状态（引擎事务内）
   }
   ```
4. **注册**：`Biz/ServiceCollectionExtensions.cs` 的 `AddNetBaseBiz` 中 `AddScoped<IFlowBusinessHandler, ...>`（勿用 TryAdd，多实现会互吞）

前端单据详情页嵌 `<FlowTimeline :instance-id>` 展示审批进度（`getFlowInstanceByBusiness` 换实例ID）。活样例：`Biz` 目录报销单（expense）与采购申请单（purchase_request，含金额条件分支）。
