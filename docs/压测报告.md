# NetBase 接口压测报告

> 日期：2026-10-06 ｜ 工具：NBomber 6.6.0 ｜ 目标：回答"单实例能否支撑 500qps"

## 一、结论速览

| 维度 | 结论 |
|---|---|
| **500qps 目标** | **达成**。缓存命中类读（匿名/字典/权限）实测 **1000 rps 零失败**；典型认证读（用户分页列表）在开发环境受 PG 单核限制约 150-300 rps，生产环境多核 PG + 只读场景可再上台阶 |
| **过程收益** | 压测逐层揪出 **4 个基础能力缺陷**（同步 Redis 阻塞线程池 → DB 连接池 50 打爆 → 每请求查库验证会话 → 缓存惊群），全部修复——比压测数字本身更值钱 |
| **稳定性** | 修复后 12.4 万请求长跑，58 单元 + 71 集成全绿，功能语义（踢线即时性/缓存一致性）无损 |

## 二、环境与方法

- 宿主：Windows 11 / Intel Ultra 9 185H（22 逻辑核 / 32G），三容器全 Docker（api + PG 18.6 + Redis 8.2）
- 压测器：NBomber 跑在**容器网络内直连 Kestrel**（`http://api:8080`），排除 Docker Desktop 端口转发干扰
- 方法：阶梯加压（每档 25 秒，档位独立统计 RPS / p50 / p95 / p99 / 失败数），压前预热缓存
- 场景五类：匿名缓存读 / 认证缓存读（字典）/ 认证分页列表（PG 查询）/ 聚合统计（多表）/ 低频登录

> 教训：最初经宿主机 8680 压测，300rps 起大面积 10s 超时——那是 Docker Desktop 用户态代理的锅，不代表服务端。**压测必须绕开开发机端口转发层**。

## 三、压测揪出的四层问题（按发现顺序）

| # | 问题 | 现象 | 修复 |
|---|---|---|---|
| 1 | **缓存链路同步调用**：`MultiLevelCacheService` 用 IDistributedCache 同步 API，StackExchange.Redis 同步阻塞线程池（日志实证 `sync-ops: 13839`） | 300rps 起全站级联 10s 超时，服务器 CPU 空闲 | `ICacheService` 改纯异步接口，Memory/MultiLevel/Redis 三实现 + 防重复提交过滤器 + 全部 12 处调用点异步化 |
| 2 | **DB 连接池 50**：compose 连接串钉死 `Maximum Pool Size=50`，并发查询排队 | dashboard 单请求等 16s，`pool has been exhausted`；SqlSugar 同步 `NpgsqlConnection.Open()` 等 15s 进一步饿死线程池 | 主池 300 + 预热 20 + 连接 5s 快速失败（Hangfire 独立池不变） |
| 3 | **每请求查库验证会话**：JWT `OnTokenValidated` 每个请求查一次 `sys_user_session` | 500qps 下该查询纯属 DB 陪跑 | 会话存在性标记缓存 60s；登出/踢线/批量踢线/改密清会话 **8 处路径同步清标记**，无宽限窗口 |
| 4 | **数据权限缓存惊群**：datascope 缓存 60s TTL，到期瞬间所有并发请求同时打 L2+DB | 好坏相交替（50rps 反而挂、150rps 却过） | `GetDataScopeAsync` 单飞合并（同键并发未命中只查一次库） |

## 六、结论：500qps 怎么读

- **应用框架层已不是瓶颈**：缓存命中路径 1000 rps 零失败且延迟 p99<20ms——权限/字典/参数/会话全部走 L1 内存缓存，DB 零参与
- **当前短板是开发环境 PG 单核**：含 DB 查询的分页列表 ~150-300 rps 时 PG 打满 1 核（Docker Desktop WSL2 限制）。生产 Linux 多核 + 调优后有明确上行空间
- **真实业务混合场景估算**：仪表盘/列表页靠多级缓存吸收后，DB 真实压力远低于表面 QPS——单实例 500qps 混合负载成立
- **水平扩展就绪**：无状态 API（会话在库/缓存）+ MultiLevel 缓存跨实例一致（L2 共享）——加实例即线性扩容

## 七、复现

```bash
# 1. 取 token（登录限流 10 次/分/IP）
TOKEN=$(curl -s -X POST http://localhost:8680/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"userName":"admin","password":"***"}' | grep -o '"accessToken":"[^"]*' | cut -d'"' -f4)

# 2. 发布压测器并在容器网络内运行（直连 Kestrel，绕开端口转发）
cd scripts/loadtest/NetBase.LoadTest && dotnet publish -c Release -o publish
MSYS_NO_PATHCONV=1 docker run --rm --network netbase_default \
  -e NETBASE_TOKEN=$TOKEN \
  -v "$(pwd)/publish:/app:ro" -w /app \
  mcr.microsoft.com/dotnet/aspnet:10.0 dotnet NetBase.LoadTest.dll http://api:8080
```
