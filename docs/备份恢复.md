# 备份与恢复操作手册（PostgreSQL）

> 备份链路：每日 03:00 内置作业（`sys.backup.daily`）调用 `pg_dump --format=custom` 全量导出当前库 → 写入 `Backup:Directory` → 保留期外 `.backup` 自动清理；失败经站内信通知管理员。**2026-09-25 已实测演练通过**（见文末记录）。

## 一、备份产物

- 格式：pg_dump **custom**（`--format=custom`，压缩、支持选择性恢复），文件名 `{库名}_{yyyyMMdd_HHmmss}.backup`
- 内容：完整库——业务 schema（public，全部 `sys_*`/`biz_*` 表与**软删过滤唯一索引**）+ **hangfire schema**（作业持久化状态）+ 序列/权限结构
- 存放：开发环境 `src/NetBase.Api/backup/`；容器部署在 `netbase-backup` 卷（容器内 `/app/backup`）

## 二、恢复步骤（单机 / 容器通用）

```bash
# 1. 建空目标库（恢复不覆盖运行库，先验证再切换）
docker exec netbase-pg psql -U netbase -d postgres -c "CREATE DATABASE netbase_restore;"

# 2. 恢复（--no-owner 丢掉属主；custom 格式必须用 pg_restore，不能用 psql）
docker exec netbase-pg pg_restore -U netbase -d netbase_restore --no-owner --no-privileges /tmp/备份文件.backup

# 3. 验证（行数抽样 + 索引 + Hangfire 状态）
docker exec netbase-pg psql -U netbase -d netbase_restore -c "SELECT COUNT(*) FROM sys_menu;"          # 应与备份时一致（种子基线 63）
docker exec netbase-pg psql -U netbase -d netbase_restore -c "SELECT indexname FROM pg_indexes WHERE tablename='sys_user';"  # 必须含 uk_sys_user_username（软删过滤唯一索引）
docker exec netbase-pg psql -U netbase -d netbase_restore -c "SELECT COUNT(*) FROM hangfire.job;"      # 作业状态随库恢复

# 4. 切换：停 api → 改连接串库名（或改回原库名：DROP 旧库 → ALTER DATABASE netbase_restore RENAME TO netbase）→ 起 api
```

**注意事项**：
1. 恢复前目标库必须**无连接**（`SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname='目标库' AND pid<>pg_backend_pid();`）
2. 备份文件传进容器：`docker cp 备份.backup netbase-pg:/tmp/`（Git Bash 下容器内路径写 `//tmp/` 防路径转换）
3. 恢复出的库 **JWT 密钥与用户会话都随库还原**——同密钥下旧 token 继续有效，无需强制重登；若更换了 `Jwt__SecretKey` 则全员重新登录
4. Hangfire 作业状态随库恢复，无需重新注册（api 启动时 AddOrUpdate 幂等兜底）
5. pg_dump/pg_restore 的**客户端大版本必须 ≥ 服务器大版本**（本镜像内置 postgresql-client-17 对 PG 17）；服务器小版本高无碍

## 四、容器部署链路说明

- `pg_dump` 在 **api 容器内**执行（Dockerfile 通过 PGDG 源内置 postgresql-client-17；基础镜像自带 client 版本低于服务器 17 不可用），连接参数从 `Db:ConnectionString` 自动解析，密码经 `PGPASSWORD` 环境变量传递
- 备份文件直接落在 `netbase-backup` 卷（容器内 `/app/backup`），与上传文件镜像 `files/` 同卷；无需与 db 容器共享
- 手动触发：管理端「作业管理」对 `sys.backup.daily` 执行一次，或 `curl -X POST /api/v1/monitor/job/{id}/trigger`（按控制器实际路由）
- 宿主机取备份：`docker cp netbase-api:/app/backup ./` 或 `docker volume inspect netbase_backup` 定位卷路径直接拷贝

## 五、健康自检清单（恢复后）

- [ ] `/health` 返回 Healthy（含数据库探针）
- [ ] 登录正常（密码哈希随库还原）
- [ ] 菜单/字典/参数条数与备份前一致
- [ ] 系统监控页无异常；Hangfire Dashboard 作业状态为已注册
- [ ] 新建一条业务数据成功（写路径无索引/序列冲突）
