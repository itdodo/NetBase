## 三、核心架构机制

### 3.1 泛型仓储与服务

- `IRepository<T>/Repository<T>`：CRUD、分页（排序字段反射白名单防注入）、事务（`TransactionAsync`，异常重抛）、软删除、物理删除（`DeletePhysicalWhere`，用于日志/会话等无审计价值表）
- `BaseService<T>`/`IBaseService<T>`：包装仓储的通用业务能力；具体服务继承并扩展
- **新增业务模块**：实体继承 `BaseEntity` → 服务继承 `BaseService<T>` → 在 `ServiceCollectionExtensions` 注册 → 控制器继承 `BaseController`

### 3.2 认证与授权

- **登录**：`POST /api/v1/auth/login`（PBKDF2 密码校验 + 历史 SHA256 兼容 + 验证码 + 失败锁定 + 限流）
- **令牌**：AccessToken（默认 2h）+ RefreshToken（7 天，**轮换制**——旧令牌即废），会话表 `sys_user_session` 支撑登出/踢下线/停用即时生效（`OnTokenValidated` 校验会话存在性）
- **功能权限**：`[HasPermission("sys:user:add")]` 特性 + 动态策略提供器；权限码来自菜单按钮配置，`PermissionService` 进程缓存（版本号整体失效，角色/菜单/用户角色变更自动清缓存）
- **数据权限**：见 3.4

### 3.3 审计体系

- **审计字段 AOP 兜底**：SqlSugar `DataExecuting` 自动填充 CreateTime/CreateBy/UpdateTime/UpdateBy（操作人经 `IOperatorProvider` 从 Claims 解析，显式赋值优先）；业务代码无需手动赋值
- **字段级变更审计（已闭环）**：编辑统一入口（`BaseService.UpdateWithConcurrencyCheckAsync` → `Repository.UpdateWithAuditAsync`）在乐观锁更新同时自动记录字段前后值到 `sys_change_log`（`AuditDiff` 反射 diff，password/token 等词根脱敏；冲突不落审计、无差异不记录；操作人取 `IOperatorProvider` 登录态）。查询走 `/sys/changelog/page`（权限 `monitor:changelog:list`），随日志清理作业按保留期物理删除；`Db:EnableChangeAudit=false` 时整体关闭（零额外查询开销）
- **操作日志**：`OperationLogFilter` 自动记录全部写操作（参数经 `SensitiveData` 词根脱敏：password/secret/token/credential；被前置过滤器拒绝记为失败）
- **登录日志**：成功/失败/锁定/停用全记录

### 3.4 数据权限（RBAC 第二维度）

```
SysDept（部门树） ← SysUser.DeptId
角色.DataScope 五档：1全部 2自定义(SysRoleDept) 3本部门 4本部门及以下 5仅本人
```

- 业务实体实现 `IDataScope`（`DeptId` + `OwnerUserId` 真实列）即自动纳入过滤
- `DataScopeMiddleware` 每请求 `ClearAndBackup` 后按需注入全局过滤器；**多角色取并集**（部门集合 ∪ 本人数据）
- `DataScopeService` 结果 60 秒短缓存；`FilterAll`（全部数据）零开销
- 业务代码零侵入；未实现接口的表（系统管理表）不受影响

### 3.5 主键与序列化约定（雪花 ID）

- 所有表主键为 **long 雪花 ID**（Yitter，`Db:SnowflakeWorkerId` 配置机器码，多实例必须唯一）
- 填充双通道：单条插入 AOP 自动填充；**批量 `InsertRange` 显式填充**（UNION ALL 路径 AOP 不触发——新增批量场景务必走 Repository）
- **序列化防精度丢失**：ID 语义 long 属性标注 `[JsonConverter(typeof(LongToStringConverter))]`（写为字符串、读兼容字符串/数字）；新增返回雪花值的字段**必须标注**
- 非 ID 数值字段（code/total/status）保持数字序列化
- identity 列无法原地转雪花，存量库迁移需重建

### 3.6 统一返回与异常（全局错误码体系）

- 返回体：`{ code, message, errorCode?, data?, timestamp }`——**code** 承载传输语义（200 成功 / 400 参数与业务规则 / 401 未认证 / 403 无权限 / 404 不存在 / 409 乐观锁冲突 / 500 系统级）；**errorCode** 承载全局业务错误码（`ErrorCodes` 常量，117 个，总表见 [错误码.md](错误码.md)），前端按码分支
- 业务失败抛 `BusinessException`：默认 code=400；带码写法 `throw new BusinessException("文案", ErrorCodes.XXX)`（code=400）或 `("文案", ApiResultCode.X, ErrorCodes.Y)`；乐观锁冲突 = 409 + `COMMON_CONCURRENCY_CONFLICT`（`UpdateWithConcurrencyCheckAsync`）
- **管道层与业务层同构**：JWT 认证失败（OnChallenge）返回真实 HTTP 401 + ApiResult body（`AUTH_SESSION_EXPIRED`）；无权限（OnForbidden）返回真实 HTTP 403 + body（`AUTH_FORBIDDEN`）；`/api` 未匹配路由返回真实 HTTP 404 + body（`COMMON_ROUTE_NOT_FOUND`，不再落入 SPA 回退返回 HTML）。业务错误仍保持 HTTP 200 + body.code 双轨约定
- 全局过滤器统一转换（不泄露堆栈）；模型验证失败 = 400 + `COMMON_PARAM_INVALID`；防重拒绝 = 400 + `COMMON_REPEAT_SUBMIT`；未预期异常 = 500 + `COMMON_SYSTEM_ERROR`
- 规范：新增业务异常**必须查码表赋码**（`NetBase.Common/Results/ErrorCodes.cs`）；码只增不改不删；前端镜像 `web/src/types/errorCodes.ts` 由 `scripts/gen-error-codes-ts.cjs` 生成同步；前端 reject `ApiError`（携带 code/errorCode，`silentErrorCodes` 可跳过全局提示）

### 3.7 中间件管道（顺序敏感）

```
Serilog请求日志 → 安全响应头 → CORS → HTTPS/HSTS(生产) → 限流
→ 认证 → 数据权限中间件 → 授权 → 控制器（操作日志/防重/模型验证/异常过滤器）
```

### 3.8 乐观锁并发控制

- `BaseEntity.Version`：所有表自带并发版本列（默认 0），CodeFirst 启动时自动加列
- **显式乐观锁**：`Repository.UpdateWithVersionCheckAsync` 单条 SQL 原子完成——`SET 业务列 + Version+1 WHERE 主键 AND Version=旧值`，冲突（他人已先修改）影响 0 行返回 false，成功时内存版本同步自增
- **服务层用法**：`BaseService.UpdateWithConcurrencyCheckAsync`（protected）冲突时抛 `BusinessException("数据已被他人修改，请刷新后重试")`；已接入模块：用户/角色/菜单/**部门**（2026-09-26 起，部门编辑同时落字段级变更审计）
- **跨会话陈旧检测（完整链路）**：查询返回 DTO 携带 `version` → 前端编辑表单暂存 → 保存时回传（`RoleSaveDto`/`UserUpdateDto`/`MenuSaveDto` 的可选 `version`）→ 服务端以客户端版本参与乐观锁比对（`entity.Version = dto.Version ?? entity.Version`，不传则跳过校验、兼容旧客户端）→ 他人先提交后陈旧保存被拒。用户/角色/菜单编辑已接入（前后端）
- **边界**：普通 `Update/UpdateAsync` 不校验版本（末写覆盖语义）。字典/参数/公告/岗位/文件仍为此语义（不落审计）；部门自 2026-09-26 起接入审计与并发保护
- **实现红线**：禁止用 `WhereColumns(Version)` 做版本条件更新——它会以版本列替换主键条件，相同版本的多行会被同一份实体值覆盖（集成测试实证的唯一索引冲突/批量损坏隐患）

### 3.9 工作单元过滤器

- **表**：`sys_flow_definition`（定义多版本，同编码仅一个启用版）/ `sys_flow_instance`（实例，BusinessTable+BusinessId 关联任意业务单据）/ `sys_flow_task`（审批任务）/ `sys_flow_record`（流转流水，审批时间线数据源）
- **节点 DSL**（`FlowGraph` JSON，存 NodeJson）：start → 审批（会签/或签/依次 × 审批人：指定成员/角色/部门主管[SysDept.LeaderUserId]/发起人自选）→ 条件分支（变量+操作符解释求值，`ConditionEvaluator` 纯函数）→ 抄送 → end
- **编号与分类**：流程编号系统自动生成（从 100 起自增，兼容显式指定历史编码），管理无需人工填码；`Category` 分类字段支持列表筛选与归组；单据与流程的全部关联经「单据绑定」维护，编码对业务透明；流程管理页内置「分类管理」（重命名自动合并到同名分类、删除仅限未被流程使用，`/sys/flow/def/categories|category`）
- **语义基准（抄钉钉，集成测试全覆盖）**：会签全员过/任一拒即拒；或签一人定局其余作废；依次逐人生成待办；审批人为发起人/重复审批人/为空 → 自动通过并留痕；拒绝即终态、重提走新实例；前加签并入当前节点、后加签经实例 AppendNodes 追加；撤回限发起人且无人处理前
- **岗位体系**：`sys_position`/`sys_user_position`（岗位管审批权限，角色管菜单/接口权限——两者解耦）；审批人规则支持指定岗位；用户可兼多岗；岗位管理页维护（sys:position:*）
- **驳回至节点**：审批人可选「驳回」退回本实例已走过的任一审批节点（或发起人重提）重审，实例保持运行中；退回后后续节点须重新审批（重复审批人自动通过规则自动关闭）；退回发起人生成「重新提交」待办，提交后从入口重走
- **抄送我的**：抄送按人落 `sys_flow_cc`，「个人办公 → 抄送我的」分页查看，抽屉内业务单据/审批记录双页签
- **催办/超时提醒**：发起人催办（`POST instance/{id}/urge`，4h 限频）；超时自动提醒作业 `sys.flow.remind`（每日 09:00，`sys.flow.remindDays` 天数参数，0=关闭）
- **会签通过比例**：审批节点 `ApproveRatio`（1-100%，默认 100=全员），达到 `ceil(参与人数×比例%)` 即节点通过、剩余待办作废
- **委托代理**：`sys_flow_delegate`（个人办公 → 委托设置），生效期内新生成待办自动转代理人（已生成不迁移）
- **审批统计**：`GET /sys/flow/instance/stats`（系统监控 → 审批统计）：汇总/按流程/按审批人聚合，时间范围过滤
- **业务接入（4 触点，单据零审批逻辑）**：建单据表/页 → 提交时 `FlowEngine.SubmitAsync(flowCode, businessTable, businessId, variables)` → 实现 `IFlowBusinessHandler`（**按 BusinessTable 注册**——流程编号系统自增且绑定可换，按流程编码关联会失联；GetSummary 待办标题 + OnFinished 终态回写，引擎事务内执行）→ DI 注册。样板见 `Biz` 目录报销单/采购申请单
- **单据绑定（运行时可配置）**：`sys_flow_binding` 表（业务表名 → 流程编码），`/sys/flow/binding` 管理接口 + 流程管理页「单据绑定」弹窗。解析规则：有绑定记录以绑定为准（编码留空 = 该单据不走审批，提交拒绝）；无记录回退业务代码默认编码（存量零回归）——换流程/停用审批不发版
- **API**：`/sys/flow/def`（管理，`sys:flow:*`）/ `/sys/flow/task`（待办/已办/审批/转办/加签，任务归属人校验）/ `/sys/flow/instance`（分页/详情时间线/by-business/撤回）/ `/sys/flow/submit`
- **通知**：任务生成/抄送/终态均经 `INotifyService`（站内信+SignalR 秒达，BizType=flow_task/flow_instance）；顶栏待办角标 `getFlowTodoCount`
- **前端**：`FlowTimeline`（竖向时间线）/ `ApprovalActions`（同意/拒绝/转办/加签）/ `FlowDesigner`（轻量设计器，直接产出 FlowGraph；AntFlow-Designer 无 npm 包，源码引入成本高于自建，留适配点后续可换）
- **实现红线**：引擎公开方法各自包事务，内部方法不得再开事务（UseTran 不可嵌套）；SqlSugar 查询内禁止引用宿主变量的三元表达式（翻译不稳定，按分支拆开）

### 3.10 审批流引擎（钉钉式）

- `[UnitOfWork]`（Action 特性）+ `UnitOfWorkFilter`：POST/PUT/DELETE/PATCH 的标注 Action 内全部数据库操作在同一事务中执行，正常返回提交、异常/取消回滚
- 适用跨服务/跨仓储的多表写编排（与 `Repository.TransactionAsync` 等效，免事务模板代码；控制器与仓储共用同一 Scoped 客户端）
- 机制测试见 `UnitOfWorkFilterTests`（提交/回滚/非写方法直通）

### 3.11 数据库迁移版本化

- `db/migrations/NNNN_描述.sql`（NetBase.Repository 内嵌资源）+ `DbMigrationRunner`：启动时（DbSeeder 内，CodeFirst 建表之后、种子之前）按版本号顺序执行未应用脚本，记录入 `sys_db_migration`，重复执行幂等
- 分工：CodeFirst 负责实体建表/加列；**数据回填、索引调优、不可逆或需评审的 DDL 一律走迁移脚本**
- 约定：脚本必须幂等（IF NOT EXISTS/IF EXISTS 或 to_regclass 守卫）；历史脚本禁止修改（0001_baseline 因数据库引擎切换整体移植属唯一特例）；新增变更 = 新增一个 NNNN 脚本文件；脚本用 PostgreSQL 方言（列名为小写物理名）

## 六、开发约定（新功能必读）

> 📘 **业务模块开发**（业务分支上新增业务功能）另见 [业务开发规范.md](业务开发规范.md)——目录边界、建表规范、各层模板、AI 协作约定。本节以下内容针对框架层自身开发。

1. **新增接口**：控制器继承 `BaseController`，写操作打 `[HasPermission]` + 高频创建类加 `[NoRepeatSubmit]`；操作人一律取 `OperatorName`（勿自取 User）
2. **新增表**：实体继承 `BaseEntity`；若属业务数据（有部门/归属人语义）实现 `IDataScope`；CodeFirst 自动建表，种子幂等（按唯一键判断）
3. **新增批量插入**：必须走 `Repository.InsertRange(Async)`（内部已填雪花），勿直接 `db.Insertable(List)` 裸调 ExecuteCommand（不触发填充）
4. **新增雪花返回字段**：DTO 的 long ID 属性加 `[JsonConverter(typeof(LongToStringConverter))]`，前端类型同步 string
5. **新增写操作参数含敏感信息**：确认字段名命中脱敏词根（password/token/secret/credential），否则在 `SensitiveData` 补词根
6. **前端新增列表页**：优先 `usePageList` composable；Element Plus 组件勿在 script 显式 import（绕过按需样式注入，见 Sidebar 教训）；函数式组件（ElMessage 等）需手动引样式
7. **每批次交付**：`dotnet build` 0 错误 + `dotnet test` 全通过（单元+集成）+ `npm run type-check` 零错误 + 浏览器/curl 实测 + 更新本文档
