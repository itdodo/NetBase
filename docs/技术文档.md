```
│       ├── directives/          v-permission 按钮权限指令
│       ├── layout/              主布局（侧边栏/顶栏/页签）

│       ├── utils/               auth / chart / download / format
│       └── views/               页面（dashboard/profile/login/system/monitor）
└── src/                         后端（传统三层 + 泛型化）
    ├── NetBase.Api/             API 宿主：Controllers / Filters / Auth / Middlewares
    ├── NetBase.Service/         业务逻辑：BaseService<T> + 业务服务
    ├── NetBase.Repository/      数据访问：SqlSugarContext / IRepository<T> / 审计 AOP
    ├── NetBase.Model/           实体 + DTO + 枚举（供前后端契约对齐）
    ├── NetBase.Common/          通用件：ApiResult / 异常 / 安全工具 / 缓存接口
    └── NetBase.Middleware/      备用中间件封装（缓存实现 / RabbitMQ 发布器）
tests/
└── NetBase.Tests/               单元测试（密码/策略/DTO 验证/脱敏）
```

**依赖方向**：`Api → Middleware → Service → Repository → Model → Common`（单向，禁止反向引用）。

## 三、核心架构机制

### 3.1 泛型仓储与服务

- `IRepository<T>/Repository<T>`：CRUD、分页（排序字段反射白名单防注入）、事务（`TransactionAsync`，异常重抛）、软删除、物理删除（`DeletePhysicalWhere`，用于日志/会话等无审计价值表）
- `BaseService<T>`/`IBaseService<T>`：包装仓储的通用业务能力；具体服务继承并扩展
- **新增业务模块**：实体继承 `BaseEntity` → 服务继承 `BaseService<T>` → 在 `ServiceCollectionExtensions` 注册 → 控制器继承 `BaseController`

### 3.2 认证与授权

- **登录**：`POST /api/v1/auth/login`（PBKDF2 密码校验 + 历史 SHA256 兼容 + 验证码 + 失败锁定 + 限流）
- **令牌**：AccessToken（默认 2h）+ RefreshToken（7 天，**轮换制**——旧令牌即废），会话表 `sys_user_session` 支撑登出/踢下线/停用即时生效（`OnTokenValidated` 校验会话存在性）
- **功能权限**：`[HasPermission("sys:user:add")]` 特性 + 动态策略提供器；权限码来自菜单按钮配置，`PermissionService` 进程缓存（版本号整体失效，角色/菜单/用户角色变更自动清缓存）
- **数据权限**：见 3.4

### 3.3 审计体系

- **审计字段 AOP 兜底**：SqlSugar `DataExecuting` 自动填充 CreateTime/CreateBy/UpdateTime/UpdateBy（操作人经 `IOperatorProvider` 从 Claims 解析，显式赋值优先）；业务代码无需手动赋值
- **操作日志**：`OperationLogFilter` 自动记录全部写操作（参数经 `SensitiveData` 词根脱敏：password/secret/token/credential；被前置过滤器拒绝记为失败）
- **登录日志**：成功/失败/锁定/停用全记录

### 3.4 数据权限（RBAC 第二维度）

```
SysDept（部门树） ← SysUser.DeptId
角色.DataScope 五档：1全部 2自定义(SysRoleDept) 3本部门 4本部门及以下 5仅本人
```

- 业务实体实现 `IDataScope`（`DeptId` + `OwnerUserId` 真实列）即自动纳入过滤
- `DataScopeMiddleware` 每请求 `ClearAndBackup` 后按需注入全局过滤器；**多角色取并集**（部门集合 ∪ 本人数据）
- `DataScopeService` 结果 60 秒短缓存；`FilterAll`（全部数据）零开销
- 业务代码零侵入；未实现接口的表（系统管理表）不受影响

### 3.5 主键与序列化约定（雪花 ID）

- 所有表主键为 **long 雪花 ID**（Yitter，`Db:SnowflakeWorkerId` 配置机器码，多实例必须唯一）
- 填充双通道：单条插入 AOP 自动填充；**批量 `InsertRange` 显式填充**（UNION ALL 路径 AOP 不触发——新增批量场景务必走 Repository）
- **序列化防精度丢失**：ID 语义 long 属性标注 `[JsonConverter(typeof(LongToStringConverter))]`（写为字符串、读兼容字符串/数字）；新增返回雪花值的字段**必须标注**
- 非 ID 数值字段（code/total/status）保持数字序列化
- identity 列无法原地转雪花，存量库迁移需重建

### 3.6 统一返回与异常

- 返回体：`{ code, message, data?, errorCode?, timestamp }`；`errorCode` 为可选业务错误码（如 `SYS_USER_NOT_FOUND`）
- 业务失败抛 `BusinessException`，全局过滤器统一转换（不泄露堆栈）
- 模型验证失败（DataAnnotations）与防重拒绝统一返回 `code=400`

### 3.7 中间件管道（顺序敏感）

```
Serilog请求日志 → 安全响应头 → CORS → HTTPS/HSTS(生产) → 限流
→ 认证 → 数据权限中间件 → 授权 → 控制器（操作日志/防重/模型验证/异常过滤器）
```

## 四、核心功能点清单

### 4.1 系统管理

| 功能 | 要点 | 关键权限码 |
|---|---|---|
| 用户管理 | 分页（关键字/状态/部门及以下筛选）、CRUD、分配角色、重置密码（踢下线+清失败计数）、Excel 导入/导出/模板、密码策略服务端强制 | `sys:user:list/add/edit/delete` |
| 角色管理 | CRUD（编码唯一）、分配菜单、**数据权限五档**（自定义勾选部门树）、内置 admin 角色保护 | `sys:role:*` |
| 菜单管理 | 树形 CRUD（目录/菜单/按钮三类）、动态路由数据源、权限码载体 | `sys:menu:*` |
| 部门管理 | 组织树 CRUD（父子校验/删除保护：有下级或用户禁删） | `sys:dept:*` |
| 字典管理 | 类型+数据项双表、按编码取启用项（缓存 10 分钟）、示例字典 | `sys:dict:*` |
| 参数配置 | 键值参数运行时可调（内置参数禁删/禁改键）、**已接入**：默认密码/登录锁定阈值/锁定时长/验证码开关 | `sys:config:*` |
| 通知公告 | CRUD + 顶栏铃铛提醒 + 详情 | `sys:notice:*` |

| 功能 | 要点 | 权限码 |
|---|---|---|

### 4.3 个人与安全

| 功能 | 要点 |
|---|---|
| 个人中心 | 头像上传（白名单+2MB）、资料自助维护（禁改用户名/状态） |
| 修改密码 | 验旧密码、禁新旧同密、密码策略校验、成功后全端下线 |
| 登录保护 | 验证码（`sys.captcha.enabled` 可关）+ 失败 5 次锁 10 分钟（参数可调）+ 每 IP 每分钟 10 次限流 |

### 4.4 前端核心机制

| 机制 | 说明 |
|---|---|
| 动态菜单路由 | 登录后拉 `/menu/tree`，`component` 字段映射 `views/` 页面（约定：`system/user/index` → `SystemUserView`）；新页面 = 建组件 + 配菜单，零路由代码 |
| 按钮权限 | `v-permission="'sys:user:add'"`；权限码集合来自菜单树 |
| 多页签 | 打开即登记/去重/关闭跳相邻/首页固定/关闭其他与全部/会话级持久化；页签开关即 keep-alive 缓存挂载释放 |

| 主题 | 亮/暗切换（EP dark 变量），localStorage 持久化 |
| 长整型 | 雪花 ID 后端输出字符串，前端按 string 处理（禁止对 id 做数值运算） |

## 六、开发约定（新功能必读）

> 📘 **业务模块开发**（业务分支上新增业务功能）另见 [业务开发规范.md](业务开发规范.md)——目录边界、建表规范、各层模板、AI 协作约定。本节以下内容针对框架层自身开发。

1. **新增接口**：控制器继承 `BaseController`，写操作打 `[HasPermission]` + 高频创建类加 `[NoRepeatSubmit]`；操作人一律取 `OperatorName`（勿自取 User）
2. **新增表**：实体继承 `BaseEntity`；若属业务数据（有部门/归属人语义）实现 `IDataScope`；CodeFirst 自动建表，种子幂等（按唯一键判断）
3. **新增批量插入**：必须走 `Repository.InsertRange(Async)`（内部已填雪花），勿直接 `db.Insertable(List)` 裸调 ExecuteCommand（不触发填充）
4. **新增雪花返回字段**：DTO 的 long ID 属性加 `[JsonConverter(typeof(LongToStringConverter))]`，前端类型同步 string
5. **新增写操作参数含敏感信息**：确认字段名命中脱敏词根（password/token/secret/credential），否则在 `SensitiveData` 补词根
6. **前端新增列表页**：优先 `usePageList` composable；Element Plus 组件勿在 script 显式 import（绕过按需样式注入，见 Sidebar 教训）；函数式组件（ElMessage 等）需手动引样式
7. **每批次交付**：`dotnet build` 0 错误 + `dotnet test` 全通过（单元+集成）+ `npm run type-check` 零错误 + 浏览器/curl 实测 + 更新本文档

### 3.8 集成测试

`tests/NetBase.IntegrationTests` 连接**专用测试库** `NetBase_Test`（自动建库建表，与开发库隔离；连接串见 `IntegrationFixture`，CI 用环境变量覆盖）：

- **组装与生产一致**：Repository/软删过滤器/审计 AOP/雪花填充/服务层手动 DI 组装
- **覆盖范围**：
  - 仓储层：雪花填充（含批量 UNION ALL 路径——曾捕获"延迟枚举致填充丢失"的历史 bug）、软删除/物理删除、事务回滚/提交、排序白名单防注入
  - 数据权限：五档范围语义（全部/自定义/本部门/及以下/仅本人）、多角色并集、缓存一致性
  - 服务层：审计 AOP 填充、密码策略拒绝、权限码缓存失效、消息越权、日志清理
- **运行**：`dotnet test tests/NetBase.IntegrationTests`（需本机 SqlServer）
- **数据策略**：每用例唯一编码行，互不清理互不污染；测试库可随时删库重建
