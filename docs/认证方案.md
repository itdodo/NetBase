# NetBase 认证授权方案（JWT）

> 状态：方案设计（待确认决策点后实施）

## 一、总体架构

采用 **JWT Bearer（AccessToken）+ RefreshToken + 会话表** 的混合模式：

```
登录 → 校验密码(PBKDF2) → 签发 AccessToken(2h) + RefreshToken(7d) → 写入会话表
  │
请求 → Bearer Token → JwtBearer 校验签名/过期 → OnTokenValidated 校验会话表(支持踢下线)
  │                → [HasPermission("sys:user:add")] 权限码校验（Claims 内比对，无 DB 开销）
  │
过期 → POST /auth/refresh 轮换 RefreshToken → 新 token 对（旧 RefreshToken 立即失效）
```

**为什么带会话表而不是纯无状态 JWT**：菜单中已有「在线用户」模块，企业系统需要强制下线能力（禁用账号、删除角色后立即生效、管理员踢人）。纯无状态 JWT 做不到。代价是每次请求多一次会话表主键查询（中小系统可接受，后续可加缓存）。

## 二、数据库设计

新增 `sys_user_session`（CodeFirst 自动建表）：

| 列 | 类型 | 说明 |
|---|---|---|
| Id | bigint PK | 主键 |
| UserId | bigint | 用户ID |
| TokenId | varchar(64) | AccessToken 的 jti，每次请求校验存在性 |
| RefreshTokenHash | varchar(128) | RefreshToken 的 SHA256 哈希（不存明文） |
| LoginIp | varchar(64) | 登录 IP |
| UserAgent | nvarchar(255) | 浏览器标识 |
| LoginTime | datetime | 登录时间 |
| ExpireTime | datetime | RefreshToken 过期时间（过期清理依据） |

沿用 BaseEntity（审计字段 + 软删除）。

  "SecretKey": "长度≥32的随机密钥，生产环境用环境变量覆盖",

### 3.2 接口清单（AuthController，除登录外均需认证）

| 方法 | 路由 | 说明 | 权限码 |
|---|---|---|---|
| POST | /api/auth/login | 登录（匿名）：校验账号状态/密码 → 签发双 token → 写会话 → 更新最后登录时间 | — |
| POST | /api/auth/refresh | 刷新（匿名）：RefreshToken 轮换，旧 token 立即失效 | — |
| POST | /api/auth/logout | 登出：删除当前会话 | — |
| GET | /api/auth/profile | 当前用户信息 + 权限码列表（前端恢复用） | — |
| GET | /api/auth/sessions | 在线会话分页 | monitor:online:list |
| DELETE | /api/auth/sessions/{id} | 强制下线（删除目标会话） | monitor:online:offline |

登录返回体：

```json
{
  "accessToken": "...",
  "refreshToken": "...",
  "expiresIn": 7200,
  "user": { "id": 1, "userName": "admin", "nickName": "系统管理员", "roles": [...] },
  "permissions": ["sys:user:add", "sys:user:edit", "..."]
}
```

### 3.3 Claims 设计

AccessToken 载荷：`uid`（用户ID）、`name`（用户名）、`role`（角色编码，多个）、`jti`（会话 TokenId）。
**权限码不放 Claims**（改动权限需重新登录才生效，且 token 膨胀）——改为鉴权时从缓存查询用户权限码集合：

- `IPermissionService.GetUserPermissionsAsync(userId)`：role_menu join menu 查询，进程内缓存 5 分钟（ICacheService）
- 角色/菜单变更时主动失效该缓存（现有 Service 的 AssignMenus/DeleteAsync 等方法挂钩清除）

### 3.4 权限校验（Policy-based）

```
[HasPermission("sys:user:add")]   ← 自定义 Attribute 标注在 Action 上
        ↓
PermissionAuthorizationHandler：从 endpoint metadata 取权限码
  → IPermissionService 取当前用户权限集合 → 包含则通过，否则 403
```

接口权限码映射（沿用菜单种子约定）：

| 资源 | list | add | edit（含重置密码/分配） | delete |
|---|---|---|---|---|
| 用户 | sys:user:list | sys:user:add | sys:user:edit | sys:user:delete |
| 角色 | sys:role:list | sys:role:add | sys:role:edit | sys:role:delete |
| 菜单 | sys:menu:list | sys:menu:add | sys:menu:edit | sys:menu:delete |

admin 角色（admin 用户）拥有全部菜单权限码（种子已全量授权），无需特殊放行逻辑。

### 3.5 会话校验（强制下线的实现点）

`JwtBearerOptions.OnTokenValidated`：token 签名/过期校验通过后，查会话表 `TokenId == jti` 且未过期；
不存在（已登出/被踢/会话清理）→ `context.Fail("会话已失效")` 返回 401。
停用用户、删除用户同样使会话立即失效（登出场景批量删除会话）。

### 3.6 其他

- Swagger Bearer 支持：AddOpenApi 增加 Bearer scheme，Swagger UI 出现 Authorize 按钮
- `ICurrentUserService` 无需改动（已从 `uid`/`name` Claims 解析）
- 密码校验用现有 `PasswordHelper.Verify`（PBKDF2 + 旧哈希兼容）
- 登录时更新 `SysUser.LastLoginTime`

## 四、前端设计

### 4.1 登录流程

- `stores/user.ts`：mock 登录替换为 `POST /auth/login`，token 存 localStorage（accessToken + refreshToken）
- 登录页移除"认证尚未接入"提示
- 登录成功后守卫照常拉菜单树（按钮权限码来自菜单，逻辑不变）

### 4.2 Token 静默续期（request.ts）

- 响应拦截器遇 401（且非登录/刷新接口）：用 refreshToken 调 `/auth/refresh` 换新 token 并重放原请求
- **单飞（single-flight）**：并发 401 时只发一次刷新，其余请求挂起等待刷新完成后重放；刷新失败统一清 token 跳登录
- 刷新接口本身 401 → 直接跳登录（带 redirect 回跳）

### 4.3 其他

- 退出登录调 `/auth/logout`（清理服务端会话）+ 本地清 token
- 在线用户页实现：会话分页表格（用户名/IP/登录时间/UA）+ 强制下线按钮（`v-permission="'monitor:online:offline'"`）
- 顶栏显示真实用户昵称（profile 接口）

## 五、安全要点

1. SecretKey 长度 ≥ 32，生产环境用环境变量覆盖（不入库不入 git）
2. RefreshToken 只存哈希，泄露数据库也无法直接冒用
3. 刷新轮换（rotate）：每次刷新旧 RefreshToken 作废，重放窗口极小
4. 登录失败统一提示"用户名或密码错误"，不泄露账号存在性
5. 停用/删除用户的全部会话在操作时主动清除，立即生效
6. 登录失败锁定（如 5 次锁 10 分钟）本期不实现，预留 TODO
