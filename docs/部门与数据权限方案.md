# 部门管理与数据权限方案

> 状态：待确认决策点后实施

## 一、总体设计

在现有 RBAC（功能权限）之上增加**组织维度**与**数据范围维度**：

```
SysDept（部门树） ──< SysUser.DeptId（用户挂部门）
SysRole.DataScope（数据范围：5 档） ──< SysRoleDept（自定义勾选部门）
```

## 二、数据库设计

**SysDept**（部门树，同菜单树模式）：
DeptId 主键、ParentId（0=根）、DeptName、DeptCode、Leader（负责人）、Sort、Status + BaseEntity。

**SysRole 加列**：`DataScope int`（默认 1）：
| 值 | 含义 | 过滤逻辑 |
|---|---|---|
| 1 | 全部数据 | 不加过滤 |
| 2 | 自定义 | DeptId ∈ 角色勾选部门（SysRoleDept） |
| 3 | 本部门 | DeptId = 用户所属部门 |
| 4 | 本部门及以下 | DeptId ∈ 本部门+子孙部门 |
| 5 | 仅本人 | 数据归属人 = 当前用户 |

**SysRoleDept**：RoleId + DeptId（自定义勾选）。

**SysUser 加列**：`DeptId long`（所属部门，单部门归属）。

## 三、数据权限实现（核心机制）

**接口约束 + 请求级过滤器**：

```csharp
// 业务实体实现此接口即自动纳入数据权限过滤
public interface IDataScope
{
    long DeptId { get; }          // 数据所属部门
    long? OwnerUserId { get; }    // 数据归属人（"仅本人"范围使用）
}
```

- `DataScopeService`（Scoped）：按当前用户的多角色**合并计算**可见范围，产出 `(范围类型, 部门Id集合, 当前用户Id)`
- `DataScopeMiddleware`：登录请求在管道中向 SqlSugar 当前连接追加全局过滤器
  `db.QueryFilter.AddTableFilter<IDataScope>(...)`——业务实体实现接口即自动过滤，**业务代码零侵入**
- 系统管理表（菜单/角色/参数/字典等）不实现接口，管理功能不受影响
- 未登录请求（登录/验证码）跳过；`全部数据` 范围不添加过滤器（零开销）

## 四、接口与页面

| 模块 | 内容 |
|---|---|
| 部门管理 | 树形 CRUD（`/api/v1/sys/dept`，权限码 sys:dept:*），删除校验子部门/在职用户 |
| 用户管理改造 | 表单加部门树选择、列表加部门列、按部门筛选 |
| 角色管理改造 | 数据权限下拉（5 档）+ 自定义时部门树勾选 |
| 种子 | 示例部门树（总公司/研发/市场…）、admin 挂根部门、增量菜单 sys:dept:* |

前端：部门管理页（树表格）、用户页部门选择、角色页数据权限块。

## 五、安全与边界

- 多角色范围合并策略见决策点
- 数据权限对**查询**生效；用户编辑范围外用户返回"不存在"（防越权探测）
- 内置 admin 角色固定"全部数据"
- 部门删除校验：子部门/在职用户存在时拒绝
